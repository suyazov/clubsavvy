# clubsavvy — решения по ходу работы

## 01. Форматирование и структура
- Решено хранить проектные артефакты в `clients/clubsavvy/` по формату markdown с маппингом `sync/affine-map.yml`.
- Решено привязать основной контур к странице `Проект: clubsavvy` и отдельную задачу к `clubsavvy / Задачи проекта`.
- Решено вести проект как рабочий проект, а не как подготовку кейса или публикаций.

## 02. Источник истины
- Источник для синхронизации и контроля: AFFiNE (`93fc0018-71f8-45f2-a6a0-b24e3dd84a3e`) + GitHub backup (`/opt/affine-pages-backup`).
- Для спорных данных приоритет — источник, подтверждённый в AFFiNE по текущему процессу и без секретов.

## 03. Ограничения и допущения
- Не использовать личные данные и ключи доступа в клиентских markdown.
- Не дублировать уже существующие страницы; при запуске нового клиента проверять существование `Проект: <client>`.
- На текущем этапе не использовать Kimi.
- До появления проектного результата не готовить `FACTS.md`, публичный кейс, Telegram-посты и image prompts.

## 04. Текущая рабочая логика
- Сначала собрать материалы клиента в AFFiNE.
- Затем заполнить бизнес-контекст и диагностику.
- После диагностики выбрать первый небольшой результат.
- Только после результата переходить к упаковке, если нет ограничений на публикацию.

## 05. Сокращённый первый этап
- Принято стартовать с сокращённого первого этапа за `3 000 ₽`.
- Scope этапа: чистка витрины, меню, лишних демо-разделов/страниц, удаление ненужных статей, базовая замена информации о компании и явные правки по каталогу.
- Для блока `О компании` временно использовать нейтральный шаблонный текст.
- Финальный текст `О компании` клиент сможет заменить позже.
- Не расширять этот этап до глубокой переработки сайта, SEO, рекламы, аналитики или полноценной упаковки без отдельного решения.

## 06. Входящие материалы
- Google Drive folder клиента принят как источник входящих материалов: `https://drive.google.com/drive/folders/1L7lahuU_hPdf2iPQAu1ZzyVBEgGYmP0p`.
- Важные факты из Drive нужно переносить в AFFiNE/markdown вручную и структурно, не хранить секреты и приватные данные без необходимости.
- Доступ к админке получен, но сам логин/пароль не фиксировать в AFFiNE, markdown или git.
- Создан private GitHub repo проекта: `https://github.com/suyazov/clubsavvy`.

## 07. Работа с сайтом
- Сайт `https://clubsavvy.shop/` ведётся на Bitrix / Aspro Max.
- Для первого этапа предпочтительнее скрывать или отключать демо-сущности, а не безвозвратно удалять их, если нет отдельного подтверждения на удаление.
- Явно лишние демо-части: услуги, обзор авто, бренд/блог/демо-информационные окна, демо-категория `Телефоны`.
- Категории, перечисленные клиентом, считаются приоритетом для замены изображений и визуальной чистки каталога.
- Секреты доступа не сохранять в проектных документах и не публиковать в GitHub.

## 08. Первые изменения на сайте
- Изменения выполнялись через админку Bitrix и встроенную PHP-командную строку.
- Перед изменениями созданы резервные копии файлов меню и контентных страниц в `/upload/clubsavvy_ai_backup_*`.
- Меню очищено консервативно: демо-сущности убраны из навигации, папки и страницы безвозвратно не удалялись.
- `О компании` заменено на нейтральный временный текст, потому что финальный текст клиент ещё не дал.
- `Помощь` и `Как оформить заказ` переписаны как базовая пошаговая инструкция без неподтверждённых обещаний по доставке и оплате.

## 09. Исправление меню Aspro после проверки витрины
- По скриншоту пользователя стало видно, что публичный header продолжал показывать `Проекты`.
- Причина: активный header Aspro использовал не только `/.top.menu.php`, а дополнительные файлы `/.subtop_content_multilevel.menu.php` и `/.top_content_multilevel.menu.php`.
- Эти файлы обновлены, кеш Bitrix очищен.
- На будущее при чистке Aspro Max нужно проверять все menu-файлы корня: обычные, `top_content_multilevel` и `subtop_content_multilevel`.
